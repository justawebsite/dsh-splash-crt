# dsh-splash-crt

DSH 开屏动画插件 —— **一块显像管（CRT）画面 + 循环反色扫掠**。

页面加载后全屏点亮一块 CRT 板：黑底上的 `DEEPSEEK`（白）与 `HARNESS`（蓝）荧光字，
顶部一行 TUI 命令、底部闪动 `PRESS ANY KEY TO CONTINUE`，四周是扫描线、RGB 色散、
滚动亮带、桶形畸变与暗角。**只有这一屏**，它一直亮着等你按键。

加载完成 **5 秒**后开始反色表演：一条斜向分界线从**左下角**进入、缓慢往**右上角**
行进，身后整片画面被翻成白色（黑底变白底、白字变黑字）；**整屏全白后停留 5 秒**，
分界线才再次从左下角进入，这一程把画面翻回黑色；**复原成黑后再停留 5 秒**，然后又是
下一轮白扫掠。一白一黑循环往复，直到你按任意键 / 点击，画面淡出放行。

## 反色扫掠（本插件的核心观感）

- **分界线方向**：iso 空间里的 `x·aspect + y = T` 这条线（屏幕上是 45° 的斜线），
  白色区域是 `x + y < T` 那一侧。`T` 从 `-(aspect+1)·1.02` 扫到 `+(aspect+1)·1.02`，
  两端各留 2% 余量，保证"一点没扫到"和"整屏扫完"都能真正达到。
- **行进方向**：`T` 单调增大 → 分界线从**左下角**进入、往**右上角**行进；只有左下角
  这一侧先变白。所以第一程白区从左下角长出来（不是从右上角缩回去）。
- **循环**：一程耗时 `wipeMs`（默认 **14000ms**，刻意很慢）。偶数程把扫过的区域翻成白（反色），
  奇数程把它翻回黑（恢复）；**每一程扫完都停留 `wipeHoldMs`（默认 5000ms）**——黑白两侧各停
  5 秒。停留期间分界线停在画面外、发光边也淡掉，整块板子就那么静静地摆着，然后才重新从左下角
  进入扫下一程。周期 = `2 × (wipeMs + wipeHoldMs)`（默认 38s），无限循环。
- **分界线本身**：叠了一条柔和的青色发光边（`exp(-((x+y-T)/0.035)²)·0.40`），
  黑底上是一条亮线、白底上是一条青线，两个极性都看得见。发光强度在两端按
  `smoothstep(0, 0.045, min(u, 1-u))` 淡出——否则 2% 的过扫余量会在角落里留下一块
  静止的青色斑（停留 5 秒时尤其明显）。

## 画面构成

```
┌──────────────────────── 平台层（2D canvas） ────────────────────────┐
│  > dsh web --crt-splash --profile desktop      ← 顶部 TUI 命令        │
│                                                                    │
│            DEEPSEEK        （白色荧光 + 多圈外溢辉光）               │
│            HARNESS         （蓝色荧光，`#2f6bff`）                   │
│                                                                    │
│  ──────────────────────────────                                    │
│            PRESS ANY KEY TO CONTINUE   ← 底部提示，随扫掠一起反色    │
└────────────────────────────────────────────────────────────────────┘
                    ↓ 作为纹理上传
┌────────────────── 合成层（WebGL 全屏 quad · 单 fragment shader）────┐
│ 桶形畸变 → RGB 色散 → 扫描线 → 滚动亮带 → 噪点 → 暗角 → 退出淡出     │
│ → 反色扫掠 mask（分界线两侧 mix(base, 1-base)）→ 分界线青色发光边     │
└────────────────────────────────────────────────────────────────────┘
```

两个关键点：

1. **底部提示画在平台层**（不是 DOM），所以它和字一样会被扫描线、桶形畸变和反色扫掠
   一起处理——全白时它是"白底黑字"，不会突兀地留一截纯亮 DOM。
2. **合成层用裸 WebGL**，不引 Three.js：整个浏览器半区只需要画一个全屏 quad，
   打包产物因此从 ~508 KiB 缩到 ~14 KiB（第二屏删除后 Three.js 已无用途）。

## 退出

- 第一次按键 / 点击后进入 `exiting`：`opacity` 过渡 + shader 里的 `uLevels` 一起
  在 `fadeOutMs`（默认 600ms）内淡到黑，然后移除浮层、恢复页面。
- 前 700ms 不响应退出，避免"页面刚盖上来就被误触跳过"。
- `skipMode`：`any` 点击或按键、`click` 仅点击、`key` 仅按键。F5 / F12 / Ctrl+Shift 放行不拦。
- 自举行（`lib/bootstrap.js`）保留 5s 兜底解锁：客户端要是根本没跑起来，页面不会被永久
  藏在 `visibility:hidden` 后面。正常运行中它只是清掉隐藏标记，浮层本身不透明，观感不变。

## 安装

```powershell
# 本地开发（推荐，改完重建即生效）
dsh plugin --profile <profile> add link:<本目录绝对路径>

# 或从 git / npm
dsh plugin --profile <profile> add <spec>
```

浏览器半区**不需要重启**：宿主每次都从磁盘读 `lib/client.js` 下发（还带 `X-Splash-Rev`），
刷新页面即生效。**宿主半区**（`lib/index.js`：配置项、`/dsh-splash/*` 路由）改了才需要重启
`dsh`——Node 会按模块 URL 缓存已加载的宿主模块。

卸载：

```powershell
dsh plugin --profile <profile> remove dsh-splash-crt
```

## 配置

配置写在 profile 的 `cordis.patch.yml` 插件行里（也可以只依赖默认值）：

```yaml
- id: dsh-splash-crt
  name: dsh-splash-crt
  config:
    enabled: true         # 总开关
    skipMode: any         # any | click | key —— 退出方式
    fadeOutMs: 600        # 收屏淡出（毫秒）
    bootMs: 1400          # 显像管点亮（灯丝预热）时长（毫秒）
    wipeStartMs: 5000     # 页面加载完成后多久开始反色扫掠（毫秒）
    wipeMs: 14000         # 反色分界线扫过整屏"一程"的时长（毫秒），越大越慢
    wipeHoldMs: 5000      # 每一程扫完后停留多久，分界线才再次出现（毫秒）；黑白两侧各停一次
    scanlineIntensity: 1  # 扫描线强度倍率 0..2
```

> 配置在页面下一次加载时生效（客户端每次启动都会重新拉 `/dsh-splash/settings.json`）。
> 客户端对**旧宿主**下发的键是兼容的：`bootMs` 缺省时回退到已废弃的 `screen1Ms`，
> 扫掠参数缺省时用内置默认值——所以宿主没重启也不会出错。

## 排查记录（改这里之前先看这一节）

六个症状都是真 bug，根因都不在美术参数上：

1. **插件完全没反应 + 控制台报异常** —— 页面侧自举行的**内联脚本有语法错误**。
   注入行由宿主在 `webserver/index-inject` 里推给页面，脚本一坏宿主就抛异常，页面还被
   自举行的 `visibility:hidden` 藏着。现在自举行从 `lib/bootstrap.js` 读模板，宿主侧用
   `new Function()` 做**装载期语法自检**，语法不过就不注入；兜底解锁 5s。
2. **第一屏全黑、显像管字完全不见** —— `render()` 的第一屏分支只设了 `uMode = 0`，
   **从没把 `uTex` 绑到平台层贴图**（`uTex` 初始为 `null`，唯一赋值在第二屏分支里）。
   第一屏于是采样空纹理，GPU 上只剩扫描线/噪点。**自检口径**：`debug.pixelProbe()` 里
   `platformLitShare > 0` 但 `pixels.white = 0 / black = 100` 就是"字画在平台层、没进合成"。
3. **反色扫不到四个角、画面永远无法全白** —— 桶形畸变会把画面外的 uv 判成黑，
   旧写法在那里 `return` 了纯黑，于是连反色都跳过。现在改成先算色、再 `col *= inside`
   把画面外压黑，**不提前 return**，扫掠 mask 因此覆盖整屏（含四个角）。
4. **按任意键时画面先黑一下再淡出** —— 淡出用了 `phaseT`，而切换阶段会把 `phaseT` 归零，
   等于顺手把"灯丝预热"重跑了一遍。现在分成两个时钟：`plateMs`（自点亮起，驱动预热与扫掠，
   **不随阶段重置**）与 `phaseT`（只驱动退出淡出）。
5. **底部提示根本不出现** —— `drawScreen1()` 要的是 `opts.bootMs` 来算提示的淡入，
   而 `render()` 传 opts 时漏了这个字段：`smoothstep(NaN, NaN, ms)` 恒为 NaN，
   `NaN > 0.001` 为假，整段提示被跳过。**自检口径**：把平台层按行分 10 段统计点亮率，
   底部两段应该 > 1%。
6. **预览页全黑 / 像素自检不可信** —— 预览模式原来只认文档 URL 上的 `?preview=1`，
   直接开 `/preview` 会退回"正式模式"：浮层吃指针、`preserveDrawingBuffer` 被关掉，
   于是 250ms 后再读画布只能读到被清空的缓冲，看起来像没渲染。现在预览页注入的
   `window.__DSH_SPLASH_PREVIEW__` 也足以判定预览模式。

另外几条真正踩过的坑：

- **预览服务器必须发完整的禁用缓存头**：只给 `no-store` 时 headless 浏览器仍会用磁盘缓存里的
  旧 bundle，每次"修复"都像没生效（截图字节数与 SHA 完全一致就是信号）。
- **`readPixels` 的读法**：headless 下 WebGL 画布的像素只能在"渲染完的同一个任务里"读，
  或者开 `preserveDrawingBuffer`。预览模式默认开着，所以 `pixelProbe()` 与 `readPixels`
  都可以随时取证；正式模式关掉是因为它对每帧都有代价。
- **画布 `resize()` 之后必须重新 `gl.viewport`**：否则画面只画在左下角一小块。

## 构建

```powershell
pnpm install          # 只需要 esbuild
node tools/build.mjs  # → lib/client.js（单文件 IIFE，约 14 KiB）
```

浏览器半区刻意**不走 `dsh.client` 客户端模块注册表**：开屏需要一块盖住整页、
抢在首帧之前隐藏界面、并完全接管指针事件的自挂载浮层，而那条通道是给 React 槽位
组件用的。所以走宿主半区的 `webserver/index-inject` 内联行自举加载，加载失败由自己
吞掉——**绝不让宿主因为本插件起不来**。

## 预览（不用重启 DSH 就能看）

```powershell
node tools/preview-server.mjs 8791
# 起好后浏览器打开：
#   http://127.0.0.1:8791/preview   交互预览：播放/定帧/重播、关键时刻跳转、时刻滑杆、
#                                   预热/反色开始/一程时长/到位停留、退出方式、像素镜像
```

预览页 URL 参数：

| 参数 | 作用 |
| --- | --- |
| `?preview=1` | 声明预览模式。现在**可省略**：预览页注入的 `window.__DSH_SPLASH_PREVIEW__` 就足以判定 |
| `?freeze=<phase>:<秒>` | 加载后直接定帧并停住时间轴（出图用）；`phase` 取 `screen1` / `exiting` |
| `?hold=<phase>:<秒>` | 延迟一小会儿再定帧（默认 2000ms，可用 `?holdMs=` 调） |
| `?pause=1` | 首帧渲染完即停住时间轴 |
| `?bare=1` | 隐藏预览控制条 |
| `?mount=<选择器>` | 把开屏浮层挂进指定容器 |
| `?mirror=1` | 直接打开"像素镜像"（把画布原样贴成 `<img>`，headless 截图唯一可靠的方式） |

反色表演的关键时刻（默认参数下，一程 14s、停留 5s、周期 38s）：
`t=1.4s` 预热完成待机 · `t=5.0s` 分界线从左下角进入 · `t=12.0s` 半屏白 ·
`t=19.0s` 全白并开始停留 · `t=21.5s` 停留中（分界线不在画面里）·
`t=24.0s` 分界线再次进入、开始扫回黑色 · `t=31.0s` 半屏黑 ·
`t=38.0s` 全黑并开始停留 · `t=40.5s` 停留中（画面与待机态完全一致）·
`t=43.0s` 下一轮白扫掠开始 · `t=57.0s` 又一次全白。

## 结构

| 路径 | 作用 |
| --- | --- |
| `lib/index.js` | 宿主半区：注入行注册、`/dsh-splash/client.js` 与 `/dsh-splash/settings.json` |
| `lib/bootstrap.js` | 页面侧自举行（先藏界面，再自建 `<script>` 拉客户端，失败即放行） |
| `src/client/index.js` | 浏览器半区源码：平台层绘制、WebGL 合成 pass、反色扫掠、退出 |
| `lib/client.js` | esbuild 打包产物（无外部依赖） |
| `tools/build.mjs` | 构建脚本 |
| `tools/preview-server.mjs` | 预览静态服务器（必须用它，见上文的缓存头原因） |
| `tools/preview.html` | 交互预览页 |
| `cordis.patch.yml` | bundle 挂载声明 |

## 已知边界

- 需要 WebGL。拿不到上下文时客户端直接抛错放行界面（不会卡在隐藏态）。
- 内部渲染分辨率上限约 1600px 宽（CRT 该有的粗颗粒，也保证满帧）。
- 反色扫掠是**逐像素真反色**（`mix(base, 1-base, mask)`），不是"再画一遍反配色"。
- 分界线固定 45°（按 aspect 补偿），不跟随窗口比例变形。
